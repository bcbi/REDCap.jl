REDCap

A Julia wrapper for the REDCap API

Clients

Credentials live on a client, which every API function takes as its first argument:

using REDCap
project = REDCapProject()   # url and token from ENV
records = export_records(project; fields=[:record_id, :age])
  • REDCapProject(; url, token) holds a 32-character project token. url defaults to ENV["REDCAP_API_URL"] and token to ENV["REDCAP_API_TOKEN"], independently, and only when the client is constructed: REDCapProject(token=ENV["STUDY_B_TOKEN"]) works.
  • REDCapSuperUser(; url, token) holds a 64-character super token (ENV["REDCAP_API_SUPER_TOKEN"]). It can only call create_project, which returns a REDCapProject for the new project, and export_version.
  • The URL must look like https://example.org/redcap/api/ (plain http:// only with allow_insecure=true), and tokens must be uppercase hexadecimal of the right length.
  • Clients are immutable, and printing one shows only the token's last four characters. There is no global default client.

Import data

Imports take data as any Tables.jl table (e.g. a DataFrame), a single row (a NamedTuple or Dict), or a vector of rows. A NamedTuple or Dict whose values are all vectors is a column table, e.g. Dict("record_id" => ["1", "2"], "age" => [63, 70]); the vectors must have the same length. To import a single row whose values are all vectors, wrap it in a vector. The data is sent as JSON. Values are sent as strings; missing and nothing become blanks, Bools become 1/0, and nested Dicts (e.g. per-instrument user rights) become JSON objects. Floating-point numbers are written in plain decimal notation with the shortest digits that round-trip, without an exponent or a trailing .0 (1e-5 as 0.00001, 30.0 as 30). For fields validated to a fixed number of decimal places (e.g. number_2dp), pass the values as formatted strings. Dates are written as yyyy-mm-dd, or as mm/dd/yyyy or dd/mm/yyyy when a record import is given dateFormat=:MDY or :DMY; other date and time values (e.g. DateTime) must be passed as formatted strings.

To send data that is already formatted, pass an IO or a REDCapFile, together with format (:csv, :json, :xml, or :odm for records):

import_records(project; data=REDCapFile("records.csv"), format=:csv)

A plain String is never accepted as data.

Every function returns one fixed type, stated in its docstring:

A REDCapTable is a Tables.jl column table: use t[:age], or DataFrame(t). Values stay exactly as REDCap sends them, usually strings, with no type conversion; empty values stay empty strings.

Raw IO methods

Table exports, file exports and export_project_XML also have a method with an IO second argument, which writes REDCap's raw response to it and returns nothing. For table exports, format (:csv, :json, :xml; also :odm for records) is required and only exists on these methods:

open(io -> export_records(project, io; format=:csv), "records.csv", "w")

Destructive functions

Functions that erase or replace existing data have docstrings that open with a warning: overwrite_records, delete_records, import_metadata, replace_arms, delete_arms, replace_events, delete_events, delete_DAGs, import_file, delete_file, delete_file_from_file_repository, import_instrument_event_mappings, import_repeating_instruments_and_events, delete_users and delete_user_roles.

Batching

export_records, import_records, import_records_ids, overwrite_records and delete_records accept batchsize, to split large requests (which can time out, or exceed PHP's max_input_vars) into requests of at most that many records, sent one at a time. All rows of one record stay together. Batching is opt-in, and batched calls are not atomic: if a batch fails (with an error from REDCap, or a timeout or connection error), a REDCapBatchError reports the progress and wraps the original error, and earlier batches stay applied.

Errors

  • Any non-2xx response throws a REDCapError with the HTTP status, REDCap's error message and the function name. There are no automatic retries, since writes are not safe to repeat.
  • In a batched call, any failure of a batch, including a timeout or connection error, throws a REDCapBatchError that wraps it.
  • Invalid arguments throw ArgumentError (or MethodError/UndefKeywordError for missing or unsupported keywords) before any request is sent.
  • Tokens never appear in errors or in the @debug request logs (ENV["JULIA_DEBUG"] = "REDCap").

Testing your code

Clients take a transport. MockTransport records requests and answers with canned responses, without a network; RecordingTransport saves real responses as fixtures.

Example

using REDCap, DataFrames

project = REDCapProject(url="https://redcap.example.org/api/", token=ENV["STUDY_TOKEN"])

export_version(project)                       # v"15.0.1"
metadata = export_metadata(project) |> DataFrame

# Import rows; blanks are ignored and existing values are kept
import_records(project; data=[
    (record_id="1", redcap_event_name="baseline_arm_1", age="34"),
    (record_id="2", redcap_event_name="baseline_arm_1", age="41"),
])                                            # 2

# Export, in batches of 500 records
records = export_records(project; fields=[:record_id, :age], batchsize=500) |> DataFrame

# Write raw CSV to a file
open(io -> export_records(project, io; format=:csv), "records.csv", "w")

# Files
import_file(project; record=1, field=:consent, event="baseline_arm_1", file=REDCapFile("consent.pdf"))
pdf = export_file(project; record=1, field=:consent, event="baseline_arm_1")
write(pdf.filename, pdf.data)

# Destructive operations have their own names
delete_records(project; records=[1, 2])       # 2

Creating a project needs a super token:

superuser = REDCapSuperUser()                 # ENV["REDCAP_API_SUPER_TOKEN"]
project = create_project(superuser;
    data=(project_title="My study", purpose=0),
    odm=REDCapFile("template.REDCap.xml"))
