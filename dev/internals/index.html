Internals

These are not part of the public API. Every public function is a single call into this machinery: the method spec table (METHOD_SPECS) describes each function, the request builder turns a client, a spec and the user's arguments into a REDCapRequest without any I/O, a transport sends it, and the response handler converts the result to the declared return type.

REDCap.MethodSpec — Type
MethodSpec

Describes one public API function.

  • name: the Julia function name
  • content, action: REDCap's content and action parameters (action may be nothing)
  • client: the client type the function accepts
  • data: :required for imports, :none otherwise
  • required, optional: REDCap parameters the user passes as keywords (besides data)
  • returns: the return kind (see RETURN_KINDS)
  • destructive: the call erases or replaces existing data
  • raw_io: a method taking an IO second argument exists, which writes the raw response
  • io_optional: extra parameters accepted only by the IO method
  • io_formats: allowed format values for the IO method; empty when the response has only one format (XML, binary files), in which case the IO method has no format
  • data_formats: allowed format values for raw (IO/REDCapFile) import data
  • single_row: data must contain exactly one row
  • json_object: table data is sent as a single JSON object instead of an array of one (requires single_row)
  • column_order: when not empty, REDCap reads table data by column position, not by name, so each row is sent with exactly these columns in this order (see order_columns)
  • upload: the function uploads a file (keywords file and filename)
  • fixed: parameters this function always sends, which the user can't set
  • batchable: the function accepts batchsize
  • overrides: per-method parameter kinds, where REDCap is inconsistent

REDCap.build_request — Method
build_request(client, spec, params; data=NoData(), format=nothing, io=false,
              file=nothing, filename=nothing) -> REDCapRequest

Build and validate the request for spec. params holds the user's REDCap parameters; entries whose value is nothing are treated as not given. For imports, data and format describe the import data; for IO exports (io=true), format is the output format. For uploads, file (an IO or REDCapFile) and filename describe the file.

Throws ArgumentError for a wrong client type, unknown, missing or invalid parameters, CSV-only parameters without CSV data or output (see check_csv_only), data that the method doesn't take or requires, or table data with a column outside spec.column_order.

REDCap.csv_header_end — Method
csv_header_end(body) -> Union{Int, Nothing}

Index of the newline that ends the header record of a CSV body, or nothing if the body has no complete header. Newlines inside quoted cells do not end the record: with rawOrLabelHeaders=:label, the header holds field labels, which may span several lines.

REDCap.date_layout — Method
date_layout(spec, given) -> DateFormat

The layout of Date values in table data: the one dateFormat asks for, if given, or yyyy-mm-dd. The value is validated as it is when sent, so an invalid dateFormat throws the same ArgumentError.

REDCap.decimal_string — Method
decimal_string(x::AbstractFloat) -> String

Format a finite x in plain decimal notation, as REDCap's number validation expects: the shortest digits that round-trip, with no exponent and no trailing .0 (1e-5 becomes "0.00001", 30.0 becomes "30", and -0.0 becomes "0").

REDCap.run_batches — Method
run_batches(f, id_batches) -> Vector

Call f(k) for each batch k in turn. If a batch throws, stop and throw a REDCapBatchError describing the progress so far. This covers any exception (a REDCapError, or a timeout or connection error from the transport), except an InterruptException, which is rethrown as is.
